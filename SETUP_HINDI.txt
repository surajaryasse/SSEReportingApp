SSE Reporting App V52 — Site Assignment & Work Report

WHAT WORKS IN THE APP
- V48 app version is visible.
- In-app Notifications page records daily reports, material requests, attendance, TBT/work permit submissions, assignments and manager-created site-to-site transfer notices.
- Queue status tracks Sent / Delivered / Seen / Accepted (per current app model).
- Site-to-site transfer notice creates a traceable notice, not a physical inventory movement.
- Push token registration and background service worker are included as optional setup components.

IMPORTANT: background/mobile push cannot work by uploading index.html alone.
1. Deploy the ZIP contents to Netlify using index.html as the site root (keep firebase-messaging-sw.js at the site root).
2. Firebase Console > Project settings > Cloud Messaging: create/use the Web Push certificate (VAPID public key). In app, Manager > Notifications > paste/save this public key.
3. The signed-in user must use the same Firebase Auth account on the HTTPS Netlify site. Tap Notifications > Enable Push on each device/browser.
4. Deploy the sender function from the included functions/ directory to the same Firebase project using Firebase CLI. The Cloud Function may require enabling billing/Blaze depending on current Firebase project requirements; check Firebase pricing before deploying.
5. Firestore security rules must permit authenticated users to write/read only their own pushTokens/{uid} document and must allow the existing appData/main access pattern already used by this app. Do NOT publish broad public read/write rules. Restrict pushTokens so users can only access their own UID document.
6. The function watches appData/main notifications array and sends FCM push messages to registered tokens matching recipient role/name. Verify Manager/Team roles and names match the app's user records.

SECURITY NOTE
- VAPID public key is not a secret. Never put service-account JSON/private keys in index.html or Netlify static files.
- Notification text is intentionally short metadata; do not include confidential report photos or sensitive details in push bodies.
- Existing appData/main is a shared document architecture. For stronger isolation and high volume, migrate to per-recipient Firestore notification documents with UID-based rules before scaling.

FUNCTION DEPLOY (from project folder after Firebase CLI login and project selection):
  cd functions
  npm install
  cd ..
  firebase deploy --only functions:dispatchSseQueuePush

This package includes source for the sender, but it is NOT deployed to Firebase by generating this ZIP.
